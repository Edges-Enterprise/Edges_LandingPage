# Xixapay API Overview

Welcome to the Xixapay API Documentation

Xixapay is a powerful, secure, and easy-to-use payment platform designed to help businesses in Nigeria seamlessly accept payments from their customers. Whether you're running an e-commerce store, a subscription-based service, or any other business that requires online payments, Xixapay simplifies the process of payment acceptance, reconciliation, and management.

Our API offers developers a comprehensive and flexible set of tools for integrating Xixapay's payment functionalities into your website or mobile app. With support for multiple payment methods, real-time notifications, and robust security features, Xixapay enables you to offer your customers a smooth, hassle-free payment experience while keeping your business operations streamlined and secure

What Can You Do with the Xixapay API?

The Xixapay API allows you to perform a variety of actions, including:

* **Accept Payments**: Seamlessly process payments from your customers using multiple payment methods such as credit/debit cards, mobile wallets, bank transfers, and more.
* **Manage Transactions**: Create payments, view the status of transactions, issue refunds, and track the progress of payments with ease.
* **Customer Management**: Create and manage customer profiles, track their payment history, and customize payment flows based on customer data.
* **Receive Real-Time Notifications**: Stay up-to-date on transaction events such as successful payments, failed payments, and refund requests via webhooks.
* **Generate Reports**: Access detailed reports on transaction history, daily sales, and more to help manage your business efficiently.

Key Features

* **Multi-Payment Method Support**: Xixapay supports a variety of payment methods to cater to different customer preferences, including cards, bank transfers, and mobile wallets.
* **Secure Payment Gateway**: Xixapay uses cutting-edge encryption and security protocols to ensure your transactions are always safe and protected from fraud.
* **Customizable Payment Flows**: Our API gives you the flexibility to create custom payment flows, including defining your own order statuses, handling partial payments, and setting up recurring payments for subscription-based businesses.
* **Easy Integration**: With a simple REST API, integration with your website or mobile app is straightforward. We also provide SDKs and libraries in multiple languages to speed up the development process.
* **Transparent Pricing**: Xixapay offers clear and predictable pricing with no hidden fees, allowing you to plan and budget effectively.

Why Use the Xixapay API?

Xixapay is more than just a payment processor—it’s a complete payment solution for Nigerian businesses, designed with ease of use, flexibility, and scalability in mind. Here’s why you should consider using the Xixapay API:

* **Reliability**: With 99.9% uptime, Xixapay ensures that your payment gateway is always up and running, so you never miss a transaction.
* **Security**: We adhere to the highest standards of payment security, including PCI-DSS compliance, to protect your business and customers.
* **Speed**: Enjoy fast transaction processing times, real-time notifications, and instant access to funds.
* **Customer Support**: Our support team is available 24/7 to help with any issues or questions you may have during integration or operations

## ***Getting Started with Xixapay API***

To get started with the Xixapay API, you’ll need to:

1. **Create an Account**: Sign up on the Xixapay dashboard and set up your business profile.
2. **Generate Your API Key**: Once registered, generate your unique API key from the dashboard. This key will authenticate your requests to the API.
3. **Integrate the API**: Use the Xixapay API documentation to integrate payment functionality into your website or app. You’ll find detailed instructions, code samples, and examples in this documentation to guide you through the process.
4. **Start Accepting Payments**: Once your integration is complete, you can start accepting payments from your customers securely and efficiently.

# Authentication Guide

To ensure the security and integrity of your API requests, Xixapay uses **API Key-based authentication**. Every request you make to the Xixapay API must include an API key in the request header to authenticate the request and verify that it comes from an authorized source.

# Error Codes & Troubleshooting

When interacting with the Xixapay API, you may encounter various errors that provide information about issues with your requests. The following table outlines common error codes, their descriptions, potential causes, and suggested solutions.

| **HTTP Status Code**          | **Error Code**          | **Description**                                                                                   | **Example Causes**                                                                                                                                       | **Solution**                                                                                                                                             |
| ----------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **400 Bad Request**           | `bad_request`           | The request is malformed or missing required parameters.                                          | <p>- Missing required parameters (e.g., <code>amount</code>, <code>currency</code>).<br>- Invalid JSON format in the request body.</p>                   | <p>- Review the request body to ensure all required parameters are included.<br>- Validate the JSON format.</p>                                          |
| **401 Unauthorized**          | `unauthorized`          | The request is missing authentication credentials or the provided API key is invalid.             | <p>- Missing <code>Authorization</code>header.<br>- Invalid or expired API key.</p>                                                                      | <p>- Ensure the <code>Authorization</code> header is correctly set to <code>Bearer YOUR\_API\_KEY</code>.<br>- Regenerate your API key if necessary.</p> |
| **403 Forbidden**             | `forbidden`             | The server understood the request but refuses to authorize it.                                    | <p>- Insufficient API key permissions.<br>- IP whitelisting restrictions.<br>- Invalid access rights.</p>                                                | <p>- Check the API key permissions.<br>- If using IP whitelisting, ensure your IP is included.</p>                                                       |
| **404 Not Found**             | `not_found`             | The requested resource could not be found.                                                        | <p>- Incorrect URL or endpoint.<br>- Resource ID does not exist (e.g., payment, customer).</p>                                                           | <p>- Double-check the API endpoint and resource ID.<br>- Verify that the resource exists.</p>                                                            |
| **422 Unprocessable Entity**  | `unprocessable_entity`  | The server understands the request but cannot process it due to invalid or missing data.          | <p>- Invalid data (e.g., unsupported payment method).<br>- Missing or incorrect parameter values (e.g., <code>amount</code>, <code>currency</code>).</p> | <p>- Ensure all required fields are correctly formatted and valid.<br>- Check the parameter types and values.</p>                                        |
| **429 Too Many Requests**     | `too_many_requests`     | Too many requests were made in a short period, exceeding the rate limit.                          | - Making too many API calls in a short time.                                                                                                             | <p>- Implement retry logic with exponential backoff.<br>- Review the API rate limits and adjust the frequency of requests.</p>                           |
| **500 Internal Server Error** | `internal_server_error` | The server encountered an unexpected condition that prevented it from fulfilling the request.     | - Server-side issues or bugs.                                                                                                                            | <p>- Retry the request after a short wait.<br>- Contact support if the issue persists.</p>                                                               |
| **502 Bad Gateway**           | `bad_gateway`           | The Xixapay API server received an invalid response from an upstream server.                      | - Temporary issues with third-party payment providers.                                                                                                   | <p>- Retry after a short delay.<br>- Contact support if the issue persists.</p>                                                                          |
| **503 Service Unavailable**   | `service_unavailable`   | The server is currently unable to handle the request due to temporary overloading or maintenance. | - Temporary server maintenance or overload.                                                                                                              | <p>- Retry the request later.<br>- Check the Xixapay status page for any ongoing maintenance or downtime.</p>                                            |


# Customer

The **Customer** resource represents an individual user associated with a specific business. This entity is primarily used for **KYC (Know Your Customer)** verification and identity management. Each customer is linked to a business and includes personal details such as name, contact information, address, government-issued ID data, and proof of utility.

Customer records are created by businesses through the API and include validation checks to prevent duplicates and enforce identity standards (e.g., BVN/NIN formatting). Uploaded documents are stored securely and associated with the customer profile for compliance and verification purposes.

# Create Customer

* Endpoint

{% hint style="info" %}
POST: <https://api.xixapay.com/api/customer/create>
{% endhint %}

#### 📄 Description

Creates a new customer associated with a business and submits their KYC (Know Your Customer) details for verification. This includes personal information, address, ID type and number, and uploads of identification and utility bill documents.

## Request Headers

| Authorization | Beaerer {Secrete\_KEY} |
| ------------- | ---------------------- |
| api-key       | {API\_KEY}             |
| Content-Type  | application/json       |

## Request Body

| Field           | Type   | Required | Description                                  |
| --------------- | ------ | -------- | -------------------------------------------- |
| `first_name`    | string | ✅        | Customer's first name                        |
| `last_name`     | string | ✅        | Customer's last name                         |
| `email`         | string | ✅        | Valid email address                          |
| `phone_number`  | string | ✅        | Nigerian phone number (11 digits)            |
| `address`       | string | ✅        | Residential address                          |
| `state`         | string | ✅        | State of residence                           |
| `city`          | string | ✅        | City of residence                            |
| `postal_code`   | string | ✅        | Postal code                                  |
| `date_of_birth` | string | ✅        | Must be at least 14 years old (`YYYY-MM-DD`) |
| `id_type`       | string | ✅        | One of: `bvn`, `nin`                         |
| `id_number`     | string | ✅        | ID number, validated based on `id_type`      |
| `id_card`       | file   | ✅        | JPEG, PNG, or PDF file (max: 5MB)            |
| `utility_bill`  | file   | ✅        | JPEG, PNG, or PDF file (max: 5MB)            |
| `businessId`    | string | ✅        | The business ID this customer belongs to     |

📥 Example Request (JSON)

```json
// Some code

{
  "first_name": "Jane",
  "last_name": "Doe",
  "email": "jane@example.com",
  "phone_number": "08012345678",
  "address": "10 Market Street",
  "state": "Lagos",

  "date_of_birth": "2008-05-01",
  "id_type": "bvn",
  "id_number": "22123456789",
  "businessId": "abc123"
}
```

{% hint style="info" %}
🔍 Note: Files like `id_card` and `utility_bill` should be submitted as part of a `multipart/form-data` request.
{% endhint %}

✅ Successful Response

```json
{
  "status": true,
  "message": "Customer created successfully",
  "customer": {
    "customer_name": "Jane Doe",
    "customer_email": "jane@example.com",
    "customer_id": "9a4c73d7d8ff9..."
```

> `PATCH` [`https://api.xixapay.com/api/v1/updateVirtualAccountStatus`](https://api.xixapay.com/api/v1/updateVirtualAccountStatus)

## 🔐 Request Headers

| Header        | Type   | Description                                  |
| ------------- | ------ | -------------------------------------------- |
| Authorization | string | `Bearer {apiSecret}` – Your API secret token |
| Content-Type  | string | `application/json`                           |
| api-key       | string | Your API key                                 |

#### ⚠️ Notes:

* ✅ You can **only update the status of&#x20;*****static*****&#x20;virtual accounts**.
* ❌ *Dynamic* virtual accounts **cannot** have their status changed.

## 📦 Request Body

| Field               | Type   | Required | Description                                              |
| ------------------- | ------ | -------- | -------------------------------------------------------- |
| `businessId`        | string | ✅        | Your unique business identifier                          |
| `accountNumber`     | string | ✅        | The virtual account number to update                     |
| `status`            | string | ✅        | New status: `"active"` or `"deactivated"`                |
| `reason` (optional) | string | ❌        | Reason for status change (recommended when deactivating) |

▶️ Example Request: Activate Static Account

```json
{
  "businessId": "xixapay_biz_001",
  "accountNumber": "6020077501",
  "status": "active"
}
```

⛔ Example Request: Deactivate Static Account

```json
{
  "businessId": "xixapay_biz_001",
  "accountNumber": "6020077501",
  "status": "deactivated",
  "reason": "User closed business"
}

```

# Virtual / Dynamic Account Webhook

Webhooks are a powerful feature of the Xixapay API that allow your application to receive real-time notifications about events that occur on the Xixapay platform. Instead of polling the API for updates (which can be resource-intensive), you can use webhooks to automatically receive data about important events like successful payments, payment failures, refunds, and more.

In this section, we will walk you through the process of setting up webhooks, handling incoming webhook notifications, and troubleshooting common issues.

## Webhook Notification Format

The webhook will send a **JSON payload** to your endpoint, with the following structure:<br>

```json
// notificaton json format
{
  "notification_status": "payment_successful",
  "transaction_id": "xxx",
  "amount_paid": 100,
  "settlement_amount": 99.5,
  "settlement_fee": 0.5,
  "transaction_status": "success",
  "sender": {
    "name": "A D E LIMITED",
    "account_number": "****4290",
    "bank": "HYDROGEN"
  },
  "receiver": {
    "name": "adex-Abd(xixapay)",
    "account_number": "667985",
    "bank": "PalmPay"
  },
  "customer": {
    "name": "adex dev",
    "email": "adexplug@gmail.com,
    "phone": null,
    "customer_id": "xxx"
  },
  "description": "Your payment has been successfully processed.",
  "timestamp": "2024-11-22T13:00:04.256092Z"
}
```

## Field Descriptions

| **Field**                 | **Description**                                                                                                      |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `notification_status`     | The status of the notification. In this case, it indicates that the payment was successful.                          |
| `transaction_id`          | A unique identifier for the transaction. This ID can be used to track the transaction in your system.                |
| `amount_paid`             | The total amount paid by the customer (e.g., 100 units of the selected currency).                                    |
| `settlement_amount`       | The amount that will be settled to the receiver, after any fees are deducted (e.g., 99.5 units).                     |
| `settlement_fee`          | The fee charged by the payment processor or Xixapay for the transaction (e.g., 0.5 units).                           |
| `transaction_status`      | The status of the transaction. In this case, "success" indicates the transaction was completed successfully.         |
| `sender.name`             | The name of the sender or the business initiating the payment (e.g., "AGH ONLINE ACADEMY TUTORS LIMITED").           |
| `sender.account_number`   | The masked account number of the sender (last 4 digits are shown).                                                   |
| `sender.bank`             | The bank name associated with the sender (e.g., "HYDROGEN").                                                         |
| `receiver.name`           | The name of the receiver, which could be your business or another entity (e.g., "ALBARKADATASUB-Abd(Paymentpoint)"). |
| `receiver.account_number` | The account number associated with the receiver (e.g., "6679854996").                                                |
| `receiver.bank`           | The bank name associated with the receiver (e.g., "PalmPay").                                                        |
| `customer.name`           | The name of the customer who made the payment (e.g., "Abdulismail").                                                 |
| `customer.email`          | The email address of the customer (e.g., "<albarkadatasub@gmail.com>").                                              |
| `customer.phone`          | The phone number of the customer. In this case, it's null, indicating no phone number was provided.                  |
| `customer.customer_id`    | The unique customer ID assigned by your system (e.g., "xxx").                                                        |
| `description`             | A brief description of the transaction (e.g., "Your payment has been successfully processed.").                      |
| `timestamp`               | The timestamp of when the event occurred, formatted in ISO 8601 format (e.g., "2024-11-22T13:00:04.256092Z").        |

## Webhook Signature Verification

To ensure the authenticity and integrity of the webhook data, Xixapay includes a **signature** in the request header for every webhook notification sent. This signature is generated by Xixapay using your **secret security key** and the webhook payload.<br>

**1. Verifying the Webhook Signature**

When you receive a webhook, you need to:

1. Retrieve the payload sent by Xixapay in the request body.
2. Retrieve the xixapay header, which contains the expected signature for the webhook.
3. Hash the payload with your **secret security key** using the same hashing algorithm Xixapay uses (usually HMAC-SHA256).
4. Compare the computed signature with the one sent in the **xixapay** header.
5. If the signatures match, you can be confident that the webhook is authentic and hasn't been tampered with

**2. Signature Verification in Different Languages**

Here’s how to implement the signature verification in **PHP**, **Python**, and **Node.js**.<br>

{% tabs %}
{% tab title="PHP" %}

```php
<?php
// Retrieve the raw POST body and headers
$payload = file_get_contents('php://input');
$signatureHeader = $_SERVER['HTTP_XIXAPAY']; // xixapay signature header
// Your Xixapay secret security key
$secretKey = 'your-secret-key'; // Replace with your actual secret key
// Calculate the expected signature using HMAC-SHA256
$calculatedSignature = hash_hmac('sha256', $payload, $secretKey);
// Compare the calculated signature with the one from the xixapay header
if (hash_equals($calculatedSignature, $signatureHeader)) {
    // Signature is valid, proceed with handling the webhook
    echo "Webhook signature is valid!";
    // Process the payload (decode JSON, handle business logic)
    $data = json_decode($payload, true);
    // Example: Process the data (e.g., update database)
} else {
    // Signature is invalid, reject the request
    header('HTTP/1.1 400 Bad Request');
    echo "Invalid signature!";
}
?>
```

{% tab title="Python(Django)" %}

```django
import hmac
import hashlib
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.conf import settings

# Your Xixapay secret security key (set this in your settings)
SECRET_KEY = ""  # Add your secret key in xixapay

@csrf_exempt
def webhook(request):
    if request.method == 'POST':
        # Get the payload (raw body)
        payload = request.body
        
        # Get the signature from the header (xixapay)
        signature_header = request.headers.get('xixapay')

        if not signature_header:
            return JsonResponse({'error': 'No signature header'}, status=400)

        # Calculate the HMAC signature using SHA-256
        calculated_signature = hmac.new(
            SECRET_KEY.encode(), payload, hashlib.sha256
        ).hexdigest()

        # Compare the calculated signature with the one from the xixapay header
        if hmac.compare_digest(calculated_signature, signature_header):
            # Signature is valid, process the webhook data
            data = json.loads(payload)
            print("Webhook received:", data)

            # Do your processing here (e.g., update database, send email, etc.)
            return JsonResponse({'status': 'success'}, status=200)
        else:
            # Signature mismatch
            return JsonResponse({'error': 'Invalid signature'}, status=400)
    else:
        return JsonResponse({'error': 'Invalid HTTP method'}, status=405)
```
